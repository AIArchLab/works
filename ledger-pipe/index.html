Monthly reporting behind a source contract

Sources that break the contract stop the run, and the error names the source, the row and the column. No report is produced from data that failed validation.

Why the contract, not the report

Monthly reporting rarely fails because the arithmetic is wrong. It fails because the sources change shape: a renamed column, an amount with a comma or a full-width digit, one blank row, a repeated key, an impossible date. Someone then reads the sheet line by line, and one bad row means redoing the table.

The deliverable is therefore the contract: what each source must look like, checked on every run, before any number is produced. The report is the by-product.

What a rejected source looks like

VALIDATION_FAILED period=2026-09 errors=2
  Premium income row 4 [amount] cannot parse amount: '12O,000'
  Premium income row 6 [policy_no] duplicate key (first seen row 5)

VALIDATION_FAILED period=2026-09 errors=1
  Premium income row 4 [channel] required value is empty or a placeholder (NA/-/null)

Exit code 2, no report file, and a fresh LATEST.json marked failed. A previous report is deleted rather than left behind, so a directory that says failed cannot be mistaken for a current report.

Verification

SuiteCasesWhat it covers
Adjacent period12Two clean periods, missing column, malformed amount, duplicate key, impossible date, empty cell, negative amount, ratio range, full-width digits, BOM, byte-identical reruns
Adversarial15CP950 and BIG5 encodings, header whitespace, placeholder values, 1015 amounts, column reordering, 10,000 rows, duplicate headers, period gaps, repeated runs, paths with spaces, no stale report after failure
xlsx10Shared strings, inline strings, date serials, missing column, placeholder value, legacy .xls refusal, format substitution, trailing blank rows, corrupt archive, mixed formats

All three suites must pass before any claim of passing is made (tests/gate.py prints CLAIM_ALLOWED or CLAIM_BLOCKED).

Boundaries

  • No system integration, no approval workflow, no web back end
  • No cloud execution, no accounts, no telemetry
  • Reads sources; writes only to its own output folder
  • Only the first worksheet of an .xlsx is read; formulas are read as cached values

When this does not apply

  • Two-way writes into an existing system
  • A human approval step inside the flow
  • Cross-company data exchange
  • An interactive dashboard rather than a periodic report
